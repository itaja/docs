---
title: "Subscriptions API — Manage Recurring Billing Cycles"
sidebarTitle: "Subscriptions"
description: "REST API reference for Itaja subscriptions. Create, pause, cancel, and retrieve subscriptions that link customers to billing plans."
---

A **subscription** links a customer to a billing plan and instructs Itaja to charge that customer on the plan's interval automatically. Once a subscription is active, Itaja handles every billing cycle — initiating the mobile money charge, recording the resulting payment, and triggering the relevant webhook events — without any further action on your part. You can pause a subscription temporarily, resume it when you're ready, or cancel it immediately or at the end of the current billing period.

---

## Create a subscription

`POST /subscriptions`

Creates a new subscription for a customer on a billing plan. If the plan includes `trial_days`, the first charge is deferred until the trial period ends.

### Body parameters

<ParamField body="customer_id" type="string" required>
  The unique ID of the customer to subscribe (e.g., `"cust_xyz789"`). The customer must exist and have a valid phone number and provider on record.
</ParamField>

<ParamField body="plan_id" type="string" required>
  The unique ID of the billing plan to subscribe the customer to (e.g., `"plan_abc123"`). The plan must be active.
</ParamField>

<ParamField body="start_date" type="string">
  ISO 8601 date (`YYYY-MM-DD`) on which billing should begin. Defaults to today if omitted. Setting a future date schedules the subscription to activate on that date.
</ParamField>

<ParamField body="idempotency_key" type="string">
  A unique string you generate to safely retry the request without accidentally creating duplicate subscriptions. Itaja returns the original response for any subsequent request with the same key.
</ParamField>

### Request example

```bash
curl -X POST https://api.getitaja.com/v1/subscriptions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"customer_id": "cust_xyz789", "plan_id": "plan_abc123", "start_date": "2024-02-01"}'
```

### Response `201 Created`

```json
{
  "data": {
    "id": "sub_def456",
    "customer_id": "cust_xyz789",
    "plan_id": "plan_abc123",
    "status": "active",
    "current_period_start": "2024-02-01",
    "current_period_end": "2024-03-01",
    "created_at": "2024-01-20T09:00:00Z"
  }
}
```

<ResponseField name="data.id" type="string">
  Unique identifier for the subscription. Reference this ID when filtering payments or updating subscription state.
</ResponseField>

<ResponseField name="data.status" type="string">
  Current state of the subscription. Possible values: `active`, `paused`, `past_due`, `cancelled`, `trialing`.
</ResponseField>

<ResponseField name="data.current_period_start" type="string">
  ISO 8601 date marking the start of the current billing period.
</ResponseField>

<ResponseField name="data.current_period_end" type="string">
  ISO 8601 date marking the end of the current billing period. Itaja attempts the next charge on or just after this date.
</ResponseField>

## List subscriptions

`GET /subscriptions`

Returns a paginated list of subscriptions. Filter by `status`, `customer_id`, or `plan_id` to narrow results.

### Query parameters

<ParamField query="status" type="string">
  Filter by subscription status. One of `active`, `paused`, `past_due`, `cancelled`, or `trialing`.
</ParamField>

<ParamField query="customer_id" type="string">
  Return only subscriptions belonging to the specified customer.
</ParamField>

<ParamField query="plan_id" type="string">
  Return only subscriptions attached to the specified plan.
</ParamField>

<ParamField query="page" type="integer">
  Page number to retrieve. Defaults to `1`.
</ParamField>

<ParamField query="per_page" type="integer">
  Number of subscriptions per page. Defaults to `20`. Maximum is `100`.
</ParamField>

### Request example

```bash
curl 'https://api.getitaja.com/v1/subscriptions?status=active&customer_id=cust_xyz789' \
  -H "Authorization: Bearer YOUR_API_KEY"
```

### Response `200 OK`

```json
{
  "data": [
    {
      "id": "sub_def456",
      "customer_id": "cust_xyz789",
      "plan_id": "plan_abc123",
      "status": "active",
      "current_period_start": "2024-02-01",
      "current_period_end": "2024-03-01",
      "created_at": "2024-01-20T09:00:00Z"
    }
  ],
  "meta": { "total": 1, "page": 1, "per_page": 20 }
}
```

## Retrieve a subscription

`GET /subscriptions/:id`

Fetches a single subscription by its unique identifier.

### Request example

```bash
curl https://api.getitaja.com/v1/subscriptions/sub_def456 \
  -H "Authorization: Bearer YOUR_API_KEY"
```

### Response `200 OK`

```json
{
  "data": {
    "id": "sub_def456",
    "customer_id": "cust_xyz789",
    "plan_id": "plan_abc123",
    "status": "active",
    "current_period_start": "2024-02-01",
    "current_period_end": "2024-03-01",
    "created_at": "2024-01-20T09:00:00Z"
  }
}
```

## Update a subscription

`PATCH /subscriptions/:id`

Updates the state of a subscription. Use this endpoint to **pause** an active subscription or **resume** a paused one.

<Note>
  Pausing a subscription suspends billing for the current and all future periods until you resume it. Itaja does not attempt any charges while a subscription is in `paused` status.
</Note>

### Body parameters

<ParamField body="status" type="string" required>
  The target state for the subscription. Pass `"paused"` to suspend billing or `"active"` to resume a paused subscription.
</ParamField>

### Pause a subscription

Set `status` to `"paused"` to immediately suspend billing.

```bash
curl -X PATCH https://api.getitaja.com/v1/subscriptions/sub_def456 \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"status": "paused"}'
```

### Resume a subscription

Set `status` to `"active"` to re-enable billing. The next charge will occur at the start of the next billing period.

```bash
curl -X PATCH https://api.getitaja.com/v1/subscriptions/sub_def456 \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"status": "active"}'
```

### Response `200 OK`

```json
{
  "data": {
    "id": "sub_def456",
    "customer_id": "cust_xyz789",
    "plan_id": "plan_abc123",
    "status": "paused",
    "current_period_start": "2024-02-01",
    "current_period_end": "2024-03-01",
    "created_at": "2024-01-20T09:00:00Z"
  }
}
```

## Cancel a subscription

`DELETE /subscriptions/:id`

Cancels a subscription. By default, the subscription is cancelled **immediately**. Pass `cancel_at_period_end=true` to let the subscription run until the end of the current billing period before it is cancelled.

### Query parameters

<ParamField query="cancel_at_period_end" type="boolean">
  When `true`, the subscription remains active until `current_period_end` and is then cancelled automatically. Defaults to `false` (immediate cancellation).
</ParamField>

<Tip>
  Use `cancel_at_period_end=true` to give your customers the service they've already paid for while ensuring no future charges are made.
</Tip>

### Request example — immediate cancellation

```bash
curl -X DELETE https://api.getitaja.com/v1/subscriptions/sub_def456 \
  -H "Authorization: Bearer YOUR_API_KEY"
```

### Request example — cancel at period end

```bash
curl -X DELETE 'https://api.getitaja.com/v1/subscriptions/sub_def456?cancel_at_period_end=true' \
  -H "Authorization: Bearer YOUR_API_KEY"
```

### Response `200 OK`

```json
{
  "data": {
    "id": "sub_def456",
    "status": "cancelled",
    "cancelled_at": "2024-02-10T14:30:00Z",
    "cancel_at_period_end": false
  }
}
```
